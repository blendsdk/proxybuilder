## Your First Domain

Make sure you've completed [01 — Installation & Setup](01-installation-and-setup.md) before continuing. You need a running application on your server that proxybuilder will proxy traffic to.

### Example scenario

You have a Node.js API running on `127.0.0.1:3000` and you want it accessible at `https://api.example.com`.

**Prerequisites:**
- Your app is running and listening on port 3000
- The DNS A record for `api.example.com` points to your server's public IP
- Ports 80 and 443 are open (handled by `proxybuilder setup`)

### Create the domain

```bash
proxybuilder create --domain api.example.com --upstream 127.0.0.1:3000
```

That's it. Proxybuilder will:

1. ✅ Validate the domain name and upstream address
2. ✅ Create an app folder at `/opt/proxybuilder/apps/api.example.com/`
3. ✅ Request an SSL certificate from Let's Encrypt (via HTTP-01 webroot challenge)
4. ✅ Generate all nginx configuration files
5. ✅ Test the nginx config
6. ✅ Reload nginx
7. ✅ Save the domain to `proxybuilder.json`

Your site is now live at `https://api.example.com` with a valid SSL certificate.

### Verify it's working

```bash
# List all domains
proxybuilder list

# Check certificate details
proxybuilder cert-info --domain api.example.com

# Test in browser or with curl
curl -I https://api.example.com
```

## Proxy Modes

Proxybuilder supports two proxy modes that determine how much nginx handles for you.

### Passthrough Mode (default)

**Use when:** Your upstream application has its own web server (e.g., another nginx, Apache, Caddy) that handles security headers, gzip, and logging.

**What it does:**
- ✅ SSL termination (HTTPS → HTTP to upstream)
- ✅ Proxy headers (`Host`, `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`)
- ✅ Route traffic to upstream server(s)
- ✅ Maintenance mode check

**What it does NOT do:**
- ❌ No security headers (HSTS, X-Content-Type-Options, etc.)
- ❌ No gzip compression
- ❌ No favicon/robots.txt handling
- ❌ No per-domain access logging

```bash
# Passthrough is the default — these are equivalent:
proxybuilder create --domain api.example.com --upstream 127.0.0.1:3000
proxybuilder create --domain api.example.com --upstream 127.0.0.1:3000 --mode passthrough
```

### Full Mode

**Use when:** Your upstream is a bare HTTP application (Node.js, Python, Go, etc.) that doesn't have its own web server or security headers.

**Everything passthrough does, plus:**
- ✅ Security headers (HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, etc.)
- ✅ Gzip compression
- ✅ Favicon and robots.txt handling
- ✅ Per-domain access and error logging

```bash
proxybuilder create --domain app.example.com --upstream 127.0.0.1:4000 --mode full
```

### Which mode should I use?

| Scenario | Recommended Mode |
|----------|-----------------|
| Upstream is another nginx | `passthrough` |
| Upstream is Apache/Caddy | `passthrough` |
| Upstream is a raw Node.js app (Express, Fastify) | `full` |
| Upstream is a raw Python app (Flask, FastAPI) | `full` |
| Upstream is a raw Go HTTP server | `full` |
| Upstream is a Docker container with its own nginx | `passthrough` |
| You're not sure | Start with `full` — it's safer |

> 💡 **You can change the mode later** without re-creating the domain:
> ```bash
> proxybuilder update --domain app.example.com --mode passthrough
> ```

## Load Balancing (Multiple Upstreams)

Proxybuilder supports round-robin load balancing across multiple upstream servers. Pass the `--upstream` flag multiple times:

```bash
proxybuilder create --domain api.example.com \
  --upstream 127.0.0.1:3000 \
  --upstream 127.0.0.1:3001 \
  --upstream 127.0.0.1:3002
```

This generates an nginx `upstream` block that distributes requests across all three servers in round-robin fashion:

```nginx
# Generated by proxybuilder (you never edit this directly)
upstream api_example_com {
    server 127.0.0.1:3000;
    server 127.0.0.1:3001;
    server 127.0.0.1:3002;
}
```

### Update upstreams later

You can change upstreams at any time. **Note: `--upstream` on `update` replaces all existing upstreams.**

```bash
# Scale up — add a fourth server
proxybuilder update --domain api.example.com \
  --upstream 127.0.0.1:3000 \
  --upstream 127.0.0.1:3001 \
  --upstream 127.0.0.1:3002 \
  --upstream 127.0.0.1:3003

# Scale down — remove two servers
proxybuilder update --domain api.example.com \
  --upstream 127.0.0.1:3000 \
  --upstream 127.0.0.1:3001
```

## Using the Staging Environment

Let's Encrypt has [rate limits](https://letsencrypt.org/docs/rate-limits/) for production certificates. When testing or experimenting, use the `--staging` flag to avoid hitting those limits:

```bash
proxybuilder create --domain test.example.com --upstream 127.0.0.1:5000 --staging
```

> ⚠️ **Staging certificates are NOT trusted by browsers.** They are signed by a fake CA. Use them only for testing that the certificate workflow works correctly.

You can verify a staging certificate with:

```bash
proxybuilder cert-info --domain test.example.com
# Will show "Staging: Yes" in the output
```

## The `create` Command — Full Reference

```bash
proxybuilder create [options]
```

| Flag | Alias | Required | Default | Description |
|------|-------|----------|---------|-------------|
| `--domain` | `-d` | Yes | — | Domain name (or `*.example.com` for wildcard) |
| `--upstream` | `-u` | Yes | — | Upstream address(es) in `host:port` format (repeatable) |
| `--mode` | `-m` | No | `passthrough` | Proxy mode: `passthrough` or `full` |
| `--dns-provider` | | No | — | DNS provider for wildcard certs: `cloudns` or `namecheap` |
| `--staging` | `-x` | No | `false` | Use Let's Encrypt staging environment |
| `--dry-run` | | No | `false` | Show what would happen without executing |

### More examples

```bash
# Basic domain (passthrough, webroot SSL)
proxybuilder create -d api.example.com -u 127.0.0.1:3000

# Full mode with multiple upstreams
proxybuilder create -d app.example.com -u 127.0.0.1:4000 -u 127.0.0.1:4001 -m full

# Wildcard domain with DNS provider (see guides 03/04)
proxybuilder create -d "*.example.com" -u 127.0.0.1:8080 --dns-provider cloudns

# Staging cert for testing
proxybuilder create -d test.example.com -u 127.0.0.1:5000 --staging

# Preview what would happen
proxybuilder create -d api.example.com -u 127.0.0.1:3000 --dry-run
```
